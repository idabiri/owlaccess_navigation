# Data provenance

This document records where each dataset came from, how it was produced, and what limits apply to sharing it. Where something was not recorded at the time, it says so rather than guessing. File dates are taken from the files themselves (2026-11-17 to 2026-11-19). Hashes of every file are in [`FILE_MANIFEST.csv`](FILE_MANIFEST.csv).

## 1. OpenStreetMap extract: `data/outdoor/source/ksu_osm.geojson`

- **Source:** OpenStreetMap, © OpenStreetMap contributors.
- **Collection:** exported as GeoJSON for the area around the KSU campuses (file dated 2026-11-17). *The export tool and the exact query or bounding box were not recorded.*
- **Licence:** [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/). Attribution "© OpenStreetMap contributors" is required wherever the data or maps made from it are shown. Derived databases that are publicly used must be offered under the ODbL (share-alike).

## 2. Buildings and sidewalks: `buildings.geojson`, `sidewalks.geojson`, `accessibility_data/ksu_buildings.gpkg`

- **Source:** derived from the OpenStreetMap extract in QGIS (files dated 2026-11-18).
- **Processing:**
  - building polygons were separated into `buildings`, and footway and steps lines into `sidewalks`
  - the team added `building_id`, `building_name`, `building_code` and `indoor_mapping` to the buildings layer
  - the GeoPackage (EPSG:3857) is the editing layer; the GeoJSON files are CRS84 exports
- **Not field-verified.** OSM coverage of accessibility attributes is sparse: there are no `wheelchair` tags.
- **Licence:** ODbL (derivative databases of OpenStreetMap).

**QGIS project (`Navigation.qgz`).** The repository holds a sanitized copy. The QGIS "save user" name, the project author field and one absolute local path (now `./entrances_ramps.geojson`) were removed for privacy. Nothing else in the project changed. This is the only file in `data/outdoor/source/` that is not byte-identical to its original; its new hash is in the manifest.

## 3. Entrances and ramps: `entrances_ramps.geojson`, `accessibility_data/ksu_accessibility.gpkg`

- **Source:** digitized by hand in QGIS by the project team. Points were placed by reading entrance and ramp symbols on Kennesaw State University's published **Marietta Campus Accessibility Map**, after georeferencing the map image (`data/reference/georeferencing/*.points`, the `_modified.tif`).
- **Status:** every row has `verified = false`. Positions are as read from a small-scale map, 2 to 21 m from the building walls. The review is in `data/outdoor/processed/entrance_review.json`.
- **Known quirks:** one malformed row (`ENT` / `008`, `fid` null; it exists only in the GeoJSON export, not in the GeoPackage, which has 12 rows), source typos, and EPSG:3857 rather than CRS84.
- **Redistribution:** the point locations and attributes are the team's own observations. They reproduce no image content from the KSU map. Credit KSU's map as the reference used.

## 4. KSU reference maps: `data/reference/ksu_maps/` (git-ignored)

- **Source:** Kennesaw State University's published campus accessibility maps (Marietta and Kennesaw) and parking maps, as PDF. One page was exported to JPG. `KSU Marietta Campus_Accessibility Map_modified.tif` is a georeferenced copy made in QGIS. *Download URLs and dates were not recorded.*
- **Licence: unknown, so assume all rights reserved by KSU.** No licence permitting redistribution was found. These files are therefore **excluded from the public repository**. Anyone cloning the repository should obtain the maps from KSU directly.
- The QGIS project still references the TIF by relative path (`./maps/...`). Without it, that one raster layer will show as missing in QGIS, which does not affect any other layer.

## 5. Synthetic indoor package: `data/indoor/`

- **Source:** generated by `scripts/indoor/generate_indoor.py` in an AI-assisted session (Claude, Anthropic). Generator inputs:
  - the real BLD001 footprint from `buildings.geojson` (OSM way 225446888)
  - entrance hints from `entrances_ramps.geojson`
- **What is real:** only the outer footprint, approximated, with a known 0.3% north-south scale error (audit F-05). **Everything inside is invented:** room layout, room numbers and names, doors, hallways, elevators, stairs, ramps, fountains, accessibility flags, obstacles and scenarios. It is not based on KSU architectural plans.
- **Reproducibility:** the Phase 2 audit regenerated the package and found the JSON and SVG files byte-identical (SVGs after removing the C2PA block).
- **C2PA content credentials:** the copies in `app/public/data/` contain a signed `<c2pa:manifest>` block stating "Claude provided this file at the request of a user". It was added when the files were delivered and is hash-bound to the file content: editing an SVG invalidates it. The copies in `data/indoor/BLD001/` are the generator output, without the block.
- **Licence:** the footprint is OSM-derived, so treat the indoor package as ODbL-derived. The invented interior is the project's own work.

## 6. Processed outdoor data: `data/outdoor/processed/`

Produced by `scripts/integration/` from the original sources, which were read only (their SHA-256 hashes are recorded in `entrance_review.json` and re-checked by `tests/check_data_integrity.py`).

1. `build_entrance_review.py <source_dir> <out_dir> <indoor_building_dir>` writes `entrance_review.json`. It reprojects the EPSG:3857 entrance points, matches each to a building by name, and measures the distance to the wall. It proposes a snap only within 15 m:
   - 3 m or less: `source_supported`
   - more than 3 m and up to 15 m: `corrected_pending_review`
   - beyond 15 m: `needs_verification`, no snap
2. `build_outdoor_graph.py <source_dir> <out_dir>` writes `outdoor_nodes.json`, `outdoor_edges.json` and `outdoor_graph_report.json`.
   - Nodes are created only at shared vertices, way endpoints and entrance attachment points. **No proximity joins.**
   - Distances are geodesic. Speeds are assumptions (1.3 m/s footway, 0.5 m/s steps).
   - An entrance node is created only if the source point is within 5 m of its footprint, a non-steps footway is within 10 m, and the link crosses no building.
3. `verify_outdoor_graph.py <source_dir> <out_dir>` runs 16 independent checks and writes `outdoor_graph_verification.json`.
4. `filter_marietta.py <dir>` keeps the components within 2 km of BLD001. The unfiltered graph is kept in `full_sites/`.

## 7. Integrated data: `data/integrated/`

`build_unified.py <source_dir> <integration_dir> <indoor_building_dir>` writes:
- `indoor_outdoor_connectors.json`: only `entrance_2` to `oe_ENT007` is linked (provisional)
- `unified_routing_graph.json`: outdoor graph + synthetic indoor graph + connector, with obstacles and scenarios, `generated_from` hashes
- `buildings_marietta.geojson`: buildings within 1.5 km, stored in `data/outdoor/processed/`

`parity_unified.py` checks that the Python and TypeScript routers agree (2,500 cases, 0 differences when last run; needs `node` and `tsc`).

**Re-running the pipeline** needs the libraries in `scripts/requirements.txt`. The scripts write into the directory they are given, so run them into a scratch folder and compare before replacing committed files. The pipeline was **not re-run** when this repository was prepared.

## 8. App runtime data (not in the repository)

User obstacle reports are stored in `app/data/obstacle_reports.json` by the local dev server. They contain free text typed during demos, so the file is git-ignored. No accounts, names, email addresses or locations of people are collected. The position marker is simulated, and no location data is used.

## 9. Audit material: `audit/`

Reports and raw results produced during development (Phases 1, 2, 3+4, 8 and the indoor validator).
- The Phase 2 audit scripts and `scripts/indoor/ts/parity_check.mjs` hard-code the cloud-sandbox paths they were run with (`/mnt/user-data/...`, `/tmp/...`). They are kept unchanged as a record.
- Some artifacts named in the Phase 3+4 report were produced in that sandbox and are **not in this repository**: the post-fix indoor routers, `tools/parity/run_parity.sh` and `audit/pre_fix_backup/`.

## 10. Summary of redistribution limits

| Data | Can be published? | Condition |
|---|---|---|
| OSM extract and everything derived from it (buildings, sidewalks, graphs, footprint) | Yes | ODbL attribution and share-alike |
| Team-digitized entrances and ramps | Yes | Credit KSU's map as the reference; mark as unverified |
| Synthetic indoor package | Yes | Keep the "synthetic" labels; ODbL for the footprint |
| KSU PDF, JPG and TIF maps | **No** (excluded) | Only with permission from KSU |
| User obstacle reports | **No** (excluded) | Demo input, not data |
